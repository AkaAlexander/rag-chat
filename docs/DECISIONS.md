# Decisiones técnicas

| Decisión | Motivo en este proyecto | Alternativa y cuándo tendría sentido |
|---|---|---|
| Next.js App Router, React y Tailwind | Un solo proyecto sirve las pantallas y las rutas HTTP. TypeScript estricto permite seguir el contrato desde el chat hasta el proveedor. | Separar la API en otro servicio permitiría desplegar el trabajo de ingesta con recursos y ciclos de vida propios. |
| Archivos Markdown y texto UTF-8 | Permiten conservar el pasaje original y mostrar exactamente qué leyó el modelo. El límite de 256 KiB acota el trabajo por subida. | PDF exige extracción de texto y, para páginas escaneadas, OCR. Habría que verificar orden de lectura y referencias de página. |
| SQLite con better-sqlite3 y vectores JSON | Un archivo local basta para una demo y permite inspeccionar los datos. Una transacción y la restricción única sobre el hash evitan documentos parciales o duplicados por contenido. | PostgreSQL con pgvector facilitaría el acceso compartido y los índices vectoriales. El recorrido actual lee todos los fragmentos en cada consulta. Conviene medir latencia y memoria al crecer el corpus. |
| MiniLM multilingüe local | Documentos y consultas se representan en el mismo espacio vectorial para español, inglés y neerlandés. La caché evita descargar el modelo en cada arranque. | Un servicio de embeddings gestionado reduce el trabajo en el equipo y añade coste por uso y transferencia de texto. Cambiar de modelo exige volver a indexar. |
| Ventanas de 80 unidades con 16 compartidas | El solapamiento conserva parte del contexto en los bordes. Una regla fija es fácil de reproducir y probar. | Dividir por títulos, filas de tabla o tokens del modelo puede preservar mejor una cláusula larga. Las ventanas pueden separar un encabezado de sus filas. |
| Coseno seguido de coincidencias léxicas | El coseno relaciona paráfrasis. Las palabras poco frecuentes ayudan a distinguir «mudanza de domicilio» de otros permisos. El filtro de 0,35 se aplica antes de ordenar por la puntuación combinada. | Una búsqueda léxica independiente podría rescatar pasajes que quedan por debajo del filtro. Para comparar estrategias conviene medir recuperación del fragmento correcto y latencia sobre más documentos. |
| Hasta cuatro fragmentos y una búsqueda adicional | Acota el contexto y permite que el modelo reformule una pregunta cuando falte evidencia. La segunda ronda incorpora únicamente pasajes nuevos. | Una sola ronda reduce latencia. Más rondas pueden ayudar con preguntas compuestas, a costa de más llamadas y un criterio de parada más exigente. |
| Adaptadores para Ollama, OpenAI y Anthropic | El flujo RAG recibe las mismas operaciones de generación estructurada y solicitud de herramientas. Ollama usa HTTP local y los dos proveedores remotos usan sus SDK. | Un único proveedor simplificaría la implementación. El modelo elegido debe admitir el esquema de respuesta y las herramientas de su adaptador. |
| Esquema Zod, fuentes numeradas y respuesta validada | El servidor comprueba tipos e identificadores antes de presentar el texto y obtiene los extractos del índice. El nivel de confianza lo estima el modelo. | Mostrar tokens inmediatamente reduce la espera percibida, pero permite leer una referencia antes de verificarla. Una revisión humana puede detectar afirmaciones que una cita válida por sí sola no demuestra. |
| Contexto delimitado y configuración en el servidor | El prompt distingue pregunta, historial y extractos potencialmente hostiles. Las claves se leen del entorno. Las instrucciones al modelo mitigan el riesgo de inyección, con eficacia limitada por su comportamiento. | Para una biblioteca multiusuario harían falta autenticación y permisos al recuperar cada documento. Un despliegue con varias instancias también necesitaría un límite de peticiones compartido. |
| Vitest y evaluación real en SQLite en memoria | Las pruebas simuladas reproducen fallos de contratos y límites de búsqueda. Las 15 preguntas con el modelo real ejercitan el mismo flujo del chat sobre documentos conocidos. | Una evaluación humana o un conjunto más amplio mediría mejor paráfrasis, contradicciones y calidad de respuestas abiertas. Los resultados actuales corresponden al corpus y al modelo probados. |

En la ejecución registrada, Ollama obtuvo 14/15 respuestas correctas, 11/12 citas correctas y 3/3 rechazos correctos. Una petición falló y acertó al repetirse de forma aislada. El informe conserva el fallo en las métricas de la ejecución completa. [Resultados](../evals/RESULTS.md)
